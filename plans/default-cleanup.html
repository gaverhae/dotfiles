Remove the old default-pin sharing mechanism

#148 replaced the local $HOME/.default/nixpkgs.json hardlink-sharing scheme with sync-env fetching the pin straight from the dotfiles repo on GitHub, and already stopped home/bin/init-nix from using it — but left the old plumbing itself in place.

Next up

  1. Delete home/dot/default/nixpkgs.json. No remaining producer or consumer: init-nix no longer writes or links it since #148.
  2. Delete home/bin/nix-default. Its only purpose was linking a project's nix/src.json to $HOME/.default/nixpkgs.json; the --default flag that called it was dropped from init-nix in the same PR.
  3. Fix bin/go's _update: it still calls the bareword update-nixpkgs, which no longer exists — #148 renamed it to sync-env (and changed its default behavior to fetch dotfiles' own already-committed pin rather than query nixpkgs directly). Replace with sync-env --latest to keep advancing the pin on go update.
  4. On any machine you touch, manually rm -rf $HOME/.default. Deleting the repo side of a hardlink doesn't remove the machine's copy, and go sync won't clean up a file it no longer manages.
