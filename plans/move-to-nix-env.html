Move machine tools to nix-env

Replace Homebrew's brew_leaves (CLI tools) with a pinned Nix profile, following the pattern already proven by claude.nix/bin/setup-vm in the clautilde repo. Homebrew's remaining job shrinks to GUI casks on macOS; Linux machines drop Homebrew entirely.

Resolve the home/dot/ path-mapping wrinkle before writing anything. bin/go's sync walk deletes the literal substring /dot/ from each repo-relative path, which folds into a leading dot on the $HOME side (home/dot/zshrc → $HOME/.zshrc, home/dot/lein/profiles.clj → $HOME/.lein/profiles.clj).       fallback() {

trap fallback EXIT
      A crash mid-script leaves new terminals with a loud, unmistakable plain-bash session (no rc files sourced) instead of "command not found: zsh" or a failed login shell. The currently-running terminal is never affected either way, since Unix keeps an already-executing binary alive after its file is unlinked.
  7. Migrate the login shell: chsh to $HOME/.nix-profile/bin/zsh instead of /opt/homebrew/bin/zsh, and add that literal path to /etc/shells once. This is a stable path through the Nix profile/generation symlink indirection — it silently repoints at whatever zsh version tools.nix last installed, so it never needs chsh rerun on ordinary version bumps. This is a manual, per-machine action (like the existing chsh step in the README), not something a script does for you.

Non-goals

  • No home-manager. Considered and explicitly rejected: far larger surface (thousands of contributors, hundreds of files) than this repo's current hand-written, fully-understood scale justifies. The tools.nix + nix-env approach gets the declarative-list property that mattered without the adoption cost.
  • Casks stay on Homebrew. Nixpkgs' macOS GUI app support (Dock/Spotlight/LaunchServices integration) is patchy; not worth fighting for brew_casks' short list (iTerm2, MacVim, Obsidian, QLMarkdown, Rectangle, syntax-highlight, Transmission, VLC).
