Move machine tools to nix-env

Replace Homebrew's brew_leaves (CLI tools) with a pinned Nix profile, following the pattern already proven by nix/claude.nix/bin/setup-vm in the clautilde repo: a buildEnv installed via nix-env -if, using the repo's one existing nixpkgs pin — no separate pin for tools. Homebrew's remaining job shrinks to GUI casks on macOS; Linux machines drop Homebrew entirely.

Next up

  1. Relocate the repo's nix pin to home/nix/ (from top-level nix/), so it syncs to $HOME/nix/ as a sibling of $HOME/tools.nix (added next). That's what lets both bin/go (which always has a repo checkout) and home/bin/reset-nix (which doesn't, and has no stable way to find one) resolve tools.nix's relative import correctly — from either the repo copy or the synced one.
    • git mv nix home/nix.
    • shell.nix: import ./nix/nixpkgs.nix → import ./home/nix/nixpkgs.nix.
    • .envrc: watch_file nix/src.json → watch_file home/nix/src.json.
    • bin/sync-env: update its two $DOTFILES_RAW/nix/nixpkgs.nix / $DOTFILES_RAW/nix/src.json fetch URLs (the canonical source it pulls from) to $DOTFILES_RAW/home/nix/nixpkgs.nix / $DOTFILES_RAW/home/nix/src.json. Leave every other nix/... reference in sync-env, and the one in home/bin/init-nix's generated template, alone — those write into whatever project is consuming the pin, at that project's own root, unrelated to where dotfiles keeps its canonical copy.
  2. Add home/tools.nix, syncing to a visible $HOME/tools.nix the same way home/bin/* already syncs unfolded (bin/go's /dot/ path-folding only applies inside a directory literally named dot, so this needs no changes to the sync mechanism). It imports the pin as a direct sibling:

in
pkgs.buildEnv {
  name = "tools";
  paths = with pkgs; [

    direnv
    gh
    git
    gnugrep
    jq
    ncdu
    tmuxp
    tree
    vim

Three others trail the currently brew-installed version (pin lag, not a naming problem): tmuxp 1.56.0 vs. brew's 1.64.0, vim 9.1.2035 vs. 9.1.2100, watch 4.0.4 vs. 4.0.6. Not a blocker — bumping the pin (bin/sync-env --latest) closes the gap whenever it matters.
  3. Update bin/go:
    • In _sync/_install, replace the brew leaves capture-and-loop with nix-env -if "$DIR/home/tools.nix". The repo path works identically to the synced $HOME/tools.nix now that the pin lives alongside both, but bin/go already has $DIR reliably available and it sidesteps a sequencing dependency (the config-file sync loop, which creates the $HOME hardlink, would otherwise need to run before this line, not after).
    • Make the _check_binary brew guard Darwin-only in both _sync and _install, and keep the cask capture/install/reinstall loops Darwin-only as they already are.
    • In _update, gate the two remaining unconditional brew calls — brew update && brew upgrade and brew reinstall vim — behind the same Darwin check as the cask loop, so a Linux go update never touches brew at all.
    • In _update's tools step, add an explicit reapply after sync-env --latest and before the trailing go sync — bumping nix/src.json only changes what a future install would pull, it doesn't upgrade already-installed profile packages: 
        # tools
  sync-env --latest
  nix-env -if "$DIR/home/tools.nix"
  go sync
      mirroring what brew update && brew upgrade used to do.
  4. Update home/bin/reset-nix:
    • Append reprovisioning as the last step: after the fresh Nix install, run nix-env -if "$HOME/tools.nix" (no $DIR here — unlike bin/go, reset-nix never resolves a repo checkout path, so it needs the synced copy; that's exactly what relocating the pin under home/nix/ makes safe) so the script stays a genuine one-shot "wipe & restore" for machine tools too, not just project shells (which direnv already rebuilds lazily on cd — profile tools have no equivalent lazy trigger).
    • Add the safety net for the login shell: trap fallback EXIT installed near the top (after set -euo pipefail), disarmed with trap - EXIT only after the reprovision line succeeds. fallback() should be guarded to only act when the current shell is actually broken, so an unrelated early failure (e.g. a network blip during the Nix download, before the profile is even touched) doesn't needlessly clobber a still-working profile: 
      fallback() {
  if [ ! -x "$HOME/.nix-profile/bin/zsh" ]; then
    rm -f "$HOME/.nix-profile"
    mkdir -p "$HOME/.nix-profile/bin"
    ln -s /bin/bash "$HOME/.nix-profile/bin/zsh"
  fi
}
trap fallback EXIT
      The guard's protected window is narrow: reset-nix already unconditionally deletes $HOME/.nix-profile in the "Removing Nix" section, before Nix is even reinstalled — so for nearly the whole script body, zsh is genuinely absent and the fallback should fire on any exit. It only actually prevents clobbering a still-working profile in the sliver between set -euo pipefail and that deletion. A crash anywhere else leaves new terminals with a loud, unmistakable plain-bash session (no rc files sourced) instead of "command not found: zsh" or a failed login shell. The currently-running terminal is never affected either way, since Unix keeps an already-executing binary alive after its file is unlinked.
  5. Migrate the login shell: chsh to $HOME/.nix-profile/bin/zsh instead of /opt/homebrew/bin/zsh, and add that literal path to /etc/shells once. This is a stable path through the Nix profile/generation symlink indirection — it silently repoints at whatever zsh version tools.nix last installed, so it never needs chsh rerun on ordinary version bumps. This is a manual, per-machine action (like the existing chsh step in the README), not something a script does for you.
  6. Update README.md: brew install step becomes cask-only on macOS and is dropped entirely from the Linux path; new chsh target; mention tools.nix where brew_leaves is mentioned today. Also fix the Bootstrap section specifically: its one-off brew install direnv exists to break the chicken-and-egg (need direnv before go sync can do anything declarative) — that line needs to become the new manual bootstrap action, e.g. nix-env -if home/tools.nix run once by hand from the repo, not just dropped.
  7. Roll out per machine, manually, as touched. No generic upgrade script — each machine gets brought up to the new model by hand when it's next worked on, consistent with how this repo already treats machine setup.

Non-goals

  • No home-manager. Considered and explicitly rejected: far larger surface (thousands of contributors, hundreds of files) than this repo's current hand-written, fully-understood scale justifies. The tools.nix + nix-env approach gets the declarative-list property that mattered without the adoption cost.
  • Casks stay on Homebrew. Nixpkgs' macOS GUI app support (Dock/Spotlight/LaunchServices integration) is patchy; not worth fighting for brew_casks' short list (iTerm2, MacVim, Obsidian, QLMarkdown, Rectangle, syntax-highlight, Transmission, VLC).
  • No separate pin for tools. home/tools.nix rides the repo's single nix/src.json (relocated under home/, see step 1), same one shell.nix uses. No per-purpose pin proliferation.
  • No drift tripwire. Considered (tracking nix-env -q to catch stray ad hoc nix-env -i calls, the way brew_leaves catches stray brew installs), rejected as not worth the mechanism for a failure mode unlikely enough to not bother guarding against.
